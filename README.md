## 这个仓库是什么

不是课程讲义的搬运，也不是「学会之后整理好的完美笔记」。

它是**学习现场**：每篇笔记都写于刚搞懂的那一刻，每个实验都能直接运行，每次卡住和解决都记在 `progress/` 里。允许有错、允许回头改——这本身就是学习过程的一部分。

如果你也是零基础，希望这个仓库能让你看到：一个完全不懂的人，是怎么一步步把 CPU 搞明白的。

## 目标

- **近期**：跑通第一个「处理器」——支持 4 条指令、能算 `1+2+...+10` 的最小 CPU。
- **中期**：用 Verilog 写出支持 RV32E 的单周期核（D 阶段）。
- **远期**：让自己写的 CPU 跑起真实程序（C → B 阶段），理解从 `./a.out` 到晶体管之间到底发生了什么。

## 关于路线的两点改编

**这是个人学习记录，不是官方课程的替代。** 官方讲义才是权威，请以官网为准。这里只是按自己节奏做的笔记和实验。

1. **先用软件建立直觉**：官方 F 阶段用 Logisim 画电路，我先用 Python 模拟器把「取指 → 译码 → 执行 → 更新状态」的循环跑通。指令集概念完全对齐官方 sCPU（`add` / `li` / `bner0` / `out` + 数列求和），但 `python scpu.py` 就能看到结果，零安装门槛。到 E 阶段会补回 Logisim / Verilog 的硬件实现。
2. **不追进度**：官方 F+E 阶段估算 100+ 课时，并明确说明零基础应预期花费 2~3 倍时间。这里按「搞懂一个再走下一个」推进。

## 怎么学（和 AI 搭档的方式）

1. **先读笔记**，遇到不懂的名词直接问，不要攒着。
2. **再跑实验**，亲手改参数、改代码，观察输出怎么变。
3. **做完练习**，答案不重要，重要的是能用自己的话讲清楚为什么。
4. **卡住就记录**：把现象、已尝试的方法、报错原文写进 `progress/`，这是 F1「科学地提问」的核心训练。

每个阶段结束时问自己三个问题：
- 这个东西的输入是什么、输出是什么？
- 如果去掉其中一个部件，会坏在哪里？
- 我能不看笔记，把它讲给完全不懂的人听吗？
