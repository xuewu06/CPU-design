# F1 · 如何科学地提问

> 对应「一生一芯」v26.07 的 F1 任务，官方给了 2 课时。
> 把这一课放在最前面不是客套——后面 90% 的卡点，解决速度都取决于你会不会问。

---

## 为什么这是第一课

官方的项目理念里有两条很硬：

- **高标准**：不只要求你「会用」，还要求你理解原理，并**独立解决未知问题**。
- **助教只提供关键节点的引导**，不负责从头讲一遍。

这意味着：你不可能被喂着走完。遇到问题的常态是「自己查、自己试、实在不行再问」。而一个糟糕的提问，会让最愿意帮忙的人也无从下手。

> 顺带说：这条规则对**问 AI 同样成立**。「帮我看看哪错了」和「这段 BNER0 跳转后 r2 应该变成 9，但实际是 10，日志如下」，得到的帮助质量差一个数量级。

## 提问前必须做的三件事

### 1. 先自己查
- 报错原文直接搜（搜英文原文，别搜自己翻译的版本）
- 查官方文档对应章节
- 查项目 issue 里有没有人踩过同样的坑

### 2. 先复现
能否稳定重现？偶发还是必现？换个环境还出现吗？不能稳定复现的问题，先想办法让它稳定下来。

### 3. 先最小化
把问题从「我的 CPU 跑不起来」缩小到「第 5 条指令 BNER0 跳转目标算错」。
**删掉所有不影响现象的代码**——很多时候删的过程中，你自己就找到原因了。

## 一个好问题的结构

| 部分 | 要写什么 | 反例 |
|---|---|---|
| 目标 | 我最终想达成什么 | 没写，直接甩代码 |
| 环境 | OS、工具版本、相关配置 | 「我电脑上」 |
| 现象 | **实际**发生了什么（贴原文报错/输出） | 「不行」「报错了」 |
| 预期 | 我**以为**会发生什么 | 没写 |
| 已尝试 | 试过哪些方法、分别什么结果 | 「都试过了」 |
| 最小复现 | 能跑起来的最小代码 / 步骤 | 贴 300 行完整项目 |
| 猜测 | 我怀疑是哪一块（可选，但很加分） | — |

## 模板（可直接抄）

```
【目标】让 labs/F01-scpu 算出 1+2+...+10 = 55

【环境】Windows 11，Python 3.12.3，仓库 main 分支最新代码

【现象】运行 python scpu.py 后输出 45，完整输出如下：
       （贴完整输出 / 完整报错堆栈，不要截图，不要截半段）

【预期】输出 55。按我的理解循环应该执行 10 次。

【已尝试】
1. 把 BNER0 的跳转目标从 3 改成 4 → 输出变成 10，循环只跑了一轮
2. 打印每步 r2 的值：10, 9, 8, ..., 1, 0 —— 循环次数看起来是对的
3. 检查 ADD r1,r1,r2 在 r2=10 时确实得到 r1=10

【最小复现】修改 SOURCE 第 4 行后直接运行 python scpu.py 即可复现

【猜测】怀疑是累加和递减的顺序问题，但不确定该怎么改
```

## 反面例子 → 正面改写

| 别这么问 | 改成 |
|---|---|
| 「大佬救命，跑不起来」 | 「运行 `python scpu.py` 报 `ValueError: 未知指令: ADDI @ pc=3`，我加了第 5 条指令但没在 step() 里实现对应的分支」 |
| 「Verilog 综合报错怎么办」 | 「贴完整报错 + 对应 RTL 片段 + 用的综合工具版本」 |
| 「这个概念我不懂」 | 「我理解到 X 这一步，但 Y 为什么需要 Z 想不通，是不是我漏了某个前提」 |
| （发一张报错截图） | （贴文字原文——可搜索、可复制、能被引用） |

## 三个额外的习惯

1. **一个问题一个帖子**，别把五个问题塞一起。
2. **解决了要回填**：在问题末尾补上「原因是……」，下一个人（以及三个月后的你）会感谢你。
3. **不要说「我照着做了但不行」**——把「照着做的具体步骤」写出来，差异往往就藏在那里。

## 和 AI 搭档时的特别提醒

AI 会**很配合地给出看似合理的答案**，哪怕你的问题描述本身是错的。所以：

- 让 AI **先复述它对问题的理解**，再给方案
- 要求它**标明不确定的地方**，而不是给一个圆满的故事
- 代码一定要自己**跑一遍**，AI 写错循环边界是常事
- 不懂就追问「为什么」，别急着往下走——这一课的核心就是别假装懂了

## 练习

1. 故意把 `scpu.py` 里 `BNER0 r2, 3` 的 `3` 改成 `4`，观察现象，然后按上面的模板写一份提问。
2. 用一句话说清：为什么「贴报错原文」比「报错了」有用。
3. 下一次你真的卡住时，先写模板再开口——哪怕最后自己解决了，也把过程记进 `progress/`。
